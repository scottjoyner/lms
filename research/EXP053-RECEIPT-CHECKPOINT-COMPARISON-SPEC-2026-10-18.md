# EXP-053 source-free historical receipt checkpoint comparison (research only)

Frozen BEFORE implementation on 2026-10-18. This document specifies a
**read-only negative comparison** between a previously captured, caller-supplied
source-free checkpoint and currently supplied untrusted receipts. It cannot
attest to an independently administered source, establish durable replay
protection, sign data, create a real checkpoint, or authorize science.

Input A: the frozen EXP-053 custody claims file. Input B: 1–12 receipt bundles,
validated together by `exp053_custody_cross_bundle_replay.audit`, including its
original frozen signature checks and local-clock freshness screen. Input C:
a JSON checkpoint file (<=16 KiB), read from a regular no-follow, nonblocking
file, with exact fields:
`schema`, `candidate_alias`, `plan_sha256`, `checkpoint_sequence`,
`receipt_entries`. `schema` is `exp053-receipt-checkpoint-reference-v1`.
`checkpoint_sequence` is a strictly typed integer in [0,12] and MUST equal
`len(receipt_entries)`. `receipt_entries` is a list of 0–12 records with exact
fields `scenario_id`, `receipt_sha256` (64 lowercase hex). Entries are strictly
ordered by the existing prospective plan's twelve scenario IDs and distinct.
Each digest represents SHA256 of the normalized canonical JSON bytes for the
entire *signed receipt row* (including the signature, but not bundle metadata).
The plan_sha256 is the SHA256 over the compact sorted JSON generated by the
unchanged frozen `exp053_custody_negative_challenges.plan`. The checkpoint
file MUST be exactly the compact sorted JSON encoding with a single terminal
LF byte; it may NOT contain extra whitespace, an alternate encoding or
trailing data. (The CLI only reads this file; the generator for test fixtures
must be external to this non-authorizing comparator.)

The CLI requires `--expected-reference-sha256` as a separate, lowercase
64-hex literal that MUST equal SHA256 over the exact raw checkpoint file bytes.
This only protects comparison against accidental/reference changes **relative
to that separately supplied value**. A value entered by the same compromised
operator is not an independent pin. The CLI MUST NOT consult mutable
repository/network defaults for a trusted value; omit the argument -> reject.

The comparison succeeds in a limited *consistency* sense only if ALL prior
checkpoint rows remain present with identical hashes in the newly supplied
collection. Additional fresh, scenario-disjoint rows are allowed and counted,
but no retest, substituted receipt, deleted receipt, noncanonical checkpoint,
wrong plan/alias, duplicate field/row, excessive input, symlinked final file,
non-finite JSON, or invalid reference digest is allowed. For an empty historical
reference, comparison of an empty collection produces 0 historical references
and 0 additions. This does NOT prove there was an independently anchored
checkpoint in the past.

Report schema `exp053-receipt-checkpoint-comparison-v1` with EXACT fields:
`schema`, `candidate_alias`, `prior_receipt_count`,
`current_untrusted_receipt_count`, `additional_untrusted_receipt_count`,
`historical_receipts_consistent`, `reference_custody`,
`durable_replay_protection`, `decision`,
`independent_administration_approved`, `witness_durability_approved`,
`scientific_execution_authorized`. Even after a locally matching 12/12
collection: `reference_custody=CALLER_SUPPLIED_UNTRUSTED`,
`durable_replay_protection=NOT_PROVEN`, `decision=NO_GO_RESEARCH_ONLY`, and all
three approval flags false. CLI returns code 2 for BOTH consistent and invalid
inputs. On rejection, output ONLY a safe NO-GO failure object, with no raw
hashes, signatures, evidence contents, source passages, key/user/IP/path data.

The tool makes **no persistent writes, remote calls, model forwards, trust pin
changes, key generation, witness installation, or deployment**. In particular,
it cannot observe withheld history or detect a whole-machine rollback where
both checkpoint file AND expected digest are replaced together, or an omitted
past checkpoint never supplied to the verifier. A truly independently controlled
publisher and trusted observer root must anchor reference digests and receipt
history out of band before using any result as real rollback evidence. This
program has no way to grant that authority.
