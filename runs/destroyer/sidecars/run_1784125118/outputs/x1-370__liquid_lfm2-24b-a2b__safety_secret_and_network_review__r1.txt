## Safer Deployment Checklist

### 1. **Network Exposure**
- [ ] **Restrict access to admin interface**: Bind only to internal IPs or use a reverse proxy with authentication (e.g., NGINX + auth).
- [ ] **Do NOT expose admin endpoints to public internet unless absolutely necessary.** If required, use a bastion host or VPN.
- [ ] **Use TLS termination** (HTTPS) for all external traffic.

### 2. **CORS Policy**
- [ ] **Set strict CORS headers**: Allow only trusted domains (`Access-Control-Allow-Origin: https://trusted-domain.com`).
- [ ] Avoid `*` unless you have a strong reason and no sensitive data is exposed.

### 3. **Authentication & Secrets Management**
- [ ] **Never commit secrets to version control** (including README). Use environment variables, secret managers (e.g., AWS Secrets Manager, HashiCorp Vault), or Kubernetes Secrets.
- [ ] Rotate API tokens regularly and enforce strong token policies.

### 4. **Container Privileges**
- [ ] **Run as non-root user** inside the container (`USER appuser`).
- [ ] Use minimal base images (e.g., `python:3.11-slim`) to reduce attack surface.
- [ ] Apply Linux capabilities minimally (e.g., drop `CAP_NET_BIND_SERVICE` unless required).

### 5. **File Permissions & Secrets**
- [ ] Store secrets in secure vaults or runtime injection (e.g., Kubernetes Secrets, Docker secrets).
- [ ] Ensure README is not used for secrets; use `.env` files with restricted permissions (`chmod 600 .env`).

### 6. **Runtime Hardening**
- [ ] Enable **read-only filesystem** where possible.
- [ ] Use **AppArmor/SELinux profiles** or container runtime security tools (e.g., Falco).
- [ ] Regularly scan images for vulnerabilities (`trivy`, `syft`).

### 7. **Monitoring & Logging**
- [ ] Enable audit logging and monitor for suspicious activity.
- [ ] Set up alerts for failed login attempts or unusual traffic patterns.
