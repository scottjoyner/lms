## ð´ Critical Issues

### 1. Binding to `0.0.0.0` (All Interfaces)
**Risk:** Exposes the service to every network interface, including public-facing ones. Any vulnerability becomes reachable from the internet.

**Mitigation:** Bind only to `127.0.0.1` unless you have a specific reason to expose externally. If external access is needed, place it behind a reverse proxy (nginx/Caddy) with authentication and TLS termination.

```python
# â Insecure
uvicorn main:app --host 0.0.0.0 --port 8000

# Secure â bind to loopback only
uvicorn main:app --host 127.0.0.1 --port 8000
```

---

### 2. CORS Wildcard (`*`)
**Risk:** Any website can make authenticated requests to your API, enabling CSRF attacks and data exfiltration.

**Mitigation:** Restrict CORS origins explicitly. Use a whitelist of trusted domains only.

```python
# â Insecure
from fastapi.middleware.cors import CORSMiddleware
app.add_middleware(CORSMiddleware, allow_origins=["*"])

# Secure â explicit origin list
app.add_middleware(
    CORSMiddleware,
    allow_origins=["https://trusted-app.example.com"],
    allow_credentials=True,
)
```

---

### 3. API Token in README
**Risk:** Secrets stored in documentation are publicly accessible to anyone with read access. This is a **critical failure**.

**Mitigation:** Use environment variables or secret management tools (Docker secrets, AWS Secrets Manager, HashiCorp Vault). Never commit tokens to version control.

```python
# â Insecure â token in code/docs
API_TOKEN = "sk-xxxxxxxxxxxxxxxx"

# Secure â use env var at runtime
import os
API_TOKEN = os.getenv("API_TOKEN")
```

---

### 4. Running Container as Root
**Risk:** If the container is compromised, an attacker gains full host-level privileges. Privilege escalation becomes trivial.

**Mitigation:** Run containers with a non-root user. Use `USER` directive in Dockerfile and avoid `--privileged` flags.

```dockerfile
# â Insecure â runs as root by default
FROM python:3.12-slim

# Secure â explicit non-root user
FROM python:3.12-slim
RUN adduser --disabled-password appuser && \
    chown -R appuser:appuser /app
USER appuser
```

## Safer Deployment Checklist

- [ ] **Bind to `127.0.0.1`** (or use a reverse proxy with TLS + auth for external access)
- [ ] **Restrict CORS origins** to an explicit, minimal whitelist
- [ ] **Use environment variables** for all secrets â never in code or docs
- [ ] **Run as non-root user** (`appuser`, `nobody`, etc.)
- [ ] **Enable HTTPS/TLS** via a reverse proxy (nginx/Caddy) with valid certificates
- [ ] **Add authentication middleware** to the API (OAuth2, JWT, API keys validated server-side)
- [ ] **Set restrictive file permissions** (`chmod 750` for directories, `640` for files owned by app user)
- [ ] **Disable unnecessary ports/services** in container image
- [ ] **Enable audit logging** for admin endpoints
- [ ] **Use a `.env.example`** template (not `.env`) and add `.env` to `.gitignore`
