## â Issue 1: Binding to `0.0.0.0` on port 8000

**Risk:** The service listens on all network interfaces, making it reachable from external networks if the host has public IP exposure or is behind a misconfigured firewall.

### Mitigation
- Bind only to `127.0.0.1` (localhost) unless you have a specific reason for external access:
  ```python
  uvicorn main:app --host 127.0.0.1 --port 8000
  ```
- If external access is required, place the service behind a reverse proxy (e.g., nginx, Traefik) with proper TLS termination and IP allowlisting.

## â Issue 2: CORS configured as `*` (wildcard origin)

**Risk:** Any website can make authenticated requests to your API, enabling CSRF attacks and credential theft from compromised third-party sites.

### Mitigation
- Restrict CORS origins explicitly:
  ```python
  from fastapi.middleware.cors import CORSMiddleware
  
  app.add_middleware(
      CORSMiddleware,
      allow_origins=["https://your-trusted-domain.com"],
      allow_credentials=True,
      allow_methods=["GET", "POST"],
      allow_headers=["Authorization"],
  )
  ```
- If you need dynamic origins (e.g., for a SPA), use a whitelist validated server-side rather than `*`.

## â Issue 3: API token stored in README

**Risk:** Secrets committed to version control are exposed to anyone with repository access. This is one of the most common and dangerous misconfigurations.

### Mitigation
- **Never store secrets in source code, documentation, or config files.**
- Use environment variables at runtime:
  ```python
  import os
  
  API_TOKEN = os.getenv("API_TOKEN")
  if not API_TOKEN:
      raise RuntimeError("API_TOKEN must be set via environment variable")
  ```
- For container deployments, inject secrets via:
  - Kubernetes Secrets
  - Docker secrets (`--secret`)
  - CI/CD pipeline environment variables (e.g., GitHub Actions `secrets`)
- If you need a token for local development, use `.env` files **excluded from version control** (add to `.gitignore`).

---

## â Issue 4: Running container as root

**Risk:** A compromised application gains full host-level privileges. This violates the principle of least privilege and makes lateral movement trivial if the app is breached.

### Mitigation
- Create a non-root user inside the container:
  ```dockerfile
  RUN groupadd -r appuser && useradd -r -g appuser appuser
  USER appuser
  ```
- Drop all capabilities where possible:
  ```dockerfile
  COPY --chown=appuser:appuser . /app
  CMD ["sh", "-c", "exec gosu appuser python -m uvicorn main:app --host 0.0.0.0 --port 8000"]
  ```
- Use `--cap-drop=ALL` in the Docker run command and add back only what's strictly necessary (e.g., `NET_BIND_SERVICE`).
