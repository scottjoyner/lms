# Safer Deployment Checklist

## 1. Network Exposure â Restrict Access Strictly

- [ ] **Bind to `127.0.0.1` or specific internal IP** (e.g., `192.168.x.x`) instead of `0.0.0.0`. Only expose the admin server on a dedicated, non-routable interface if absolutely necessary.
- [ ] **Deploy behind a reverse proxy** (nginx, traefik, cloud provider load balancer) that handles authentication and IP whitelisting at the edge.
- [ ] **Enable firewall rules** to block all inbound traffic except from explicitly trusted IPs or CIDR ranges.

## 2. CORS â Enforce Strict Origin Policy

- [ ] **Never use `*` for CORS origins**. Replace with a specific domain: `https://yourdomain.com`.
- [ ] If you need multiple domains, list them explicitly in the `Access-Control-Allow-Origin` header.
- [ ] Set `Access-Control-Allow-Methods` to only what your API actually supports (e.g., `GET, POST`).
- [ ] Set `Access-Control-Allow-Headers` to only required headers (e.g., `Authorization`, `Content-Type`).

## 3. Credentials â Never Store Secrets in Code or README

- [ ] **Generate the API token using a secrets manager** (AWS Secrets Manager, HashiCorp Vault, Azure Key Vault, GCP Secret Manager).
- [ ] **Store tokens in environment variables**, not files. Pass them via `--env-file` at runtime or through the container's secret injection mechanism.
- [ ] **Rotate credentials regularly**. Implement a rotation script that invalidates old tokens and generates new ones.
- [ ] **Remove any hardcoded secrets** from your codebase before committing to version control.

## 4. Container Privileges â Drop Root by Default

- [ ] **Run the container as a non-root user** (e.g., `--user 1000:1000` or use a dedicated service account).
- [ ] **Drop all capabilities** unless explicitly required (`--cap-drop ALL`).
- [ ] **Mount volumes with restrictive permissions**. Use `mode=Z` for tmpfs mounts and `mode=ro` where possible.
- [ ] **Avoid sharing host directories** (e.g., `/etc`, `/var/run`) via volume mounts.

## 5. Authentication â Enforce at the API Level

- [ ] **Require authentication on all admin endpoints**. Use OAuth2, JWT with short expiry, or API key validation.
- [ ] **Implement rate limiting** to prevent brute-force attacks (e.g., `--limit 10/minute` in FastAPI).
- [ ] **Add request signing** for sensitive operations so tokens cannot be replayed.

## 6. Logging & Monitoring â Detect Compromise Early

- [ ] **Enable structured logging** with timestamps and log levels (`logging.basicConfig(level="WARNING")`).
- [ ] **Log authentication failures** separately to detect brute-force attempts.
- [ ] **Set up alerting** (PagerDuty, Slack, email) for failed login thresholds or unusual traffic patterns.
