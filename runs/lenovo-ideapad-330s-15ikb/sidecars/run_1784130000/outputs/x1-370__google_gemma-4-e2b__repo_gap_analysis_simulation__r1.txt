## 2. Implementation Cycle Plan

The plan prioritizes fixing critical security and stability issues first, followed by quality assurance, and finally scaling and hardening the architecture.

### P0: Critical Stability & Security Fixes (Immediate Action)

**Goal:** Establish a secure, stable, and minimally operational baseline.

*   **Security Deliverable:** Implement JWT-based Authentication and Authorization for all endpoints.
*   **Reliability Deliverable:** Implement basic error handling middleware (e.g., custom exception handlers) to return standardized HTTP error codes (4xx/5xx).
*   **Operational Deliverable:** Implement a Dockerfile and add a `HEALTHCHECK` command to the FastAPI service.

### P1.1: Data Integrity & Core API Hardening

**Goal:** Ensure the database is managed correctly and the core API logic is robust.

*   **Logic/Data Deliverable:** Implement Alembic (or similar) for SQLite migrations to manage schema changes reliably.
*   **Security Deliverable:** Review and sanitize all inputs, especially the direct shell command endpoint, to prevent OS command injection.
*   **Test Deliverable:** Write unit tests for core data access functions (CRUD operations).

### P1.2: Quality Assurance & Deployment Readiness

**Goal:** Establish a reliable development workflow and ensure code quality.

*   **Quality Deliverable:** Implement comprehensive test coverage (unit, integration, and basic end-to-end tests for the React dashboard).
*   **Operational Deliverable:** Set up a basic CI pipeline (e.g., GitHub Actions) to run tests and build the Docker image upon commit.
*   **Error Handling Deliverable:** Standardize error responses across the entire API using Pydantic models.

### P2: Architectural Scaling & Advanced Features

**Goal:** Improve long-term maintainability, scalability, and feature set.

*   **Architecture Deliverable:** Migrate from SQLite to a more robust relational database (e.g., PostgreSQL) if scaling is anticipated.
*   **Logic/Feature Deliverable:** Implement advanced authorization logic (Role-Based Access Control - RBAC).
*   **Maintenance Deliverable:** Refactor the application structure for better separation of concerns and dependency injection.

## 3. Implementation Gaps & Next Steps Detail

### Security Focus

1.  **Authentication Gap:** The lack of authentication is the single biggest risk. **Action:** Implement OAuth2/JWT flow immediately.
2.  **Injection Risk:** The direct shell command endpoint must be treated as highly dangerous. **Action:** Eliminate this functionality if possible, or implement strict input validation (whitelisting) and sanitization for any necessary system calls.

### Logic & Data Gaps

1.  **Migration Gap:** Using SQLite without migrations means schema changes are manual, error-prone, and impossible to reproduce in CI/CD. **Action:** Introduce an ORM with migration support (e.g., SQLAlchemy + Alembic).
2.  **Error Handling Gap:** Weak error handling leads to poor debugging and potential security leaks (e.g., exposing internal stack traces). **Action:** Implement centralized exception handlers that map internal errors to appropriate, non-descriptive HTTP responses for the client.

### Test & Operational Gaps

1.  **Test Gap:** Without tests, any future change risks breaking existing functionality silently. **Action:** Start with integration tests covering the full request lifecycle (API -> DB).
2.  **Deployment Gap:** The lack of CI/CD means deployments are manual and inconsistent. **Action:** Automate the build, test, and containerization process to ensure reproducible environments.
