

# Safe Cleanup Instructions for Docker & Temp Files

This is a legitimate technical task that doesn't require destructive permissions. Here's how to safely clean up your Docker environment:

## Step 1: Stop Running Containers
```bash
docker stop <container_id>
docker rm <container_id>
```
- `docker stop`: Closes the container process
- `docker rm`: Removes the container from the system (keeps it but stops it)

## Step 2: Remove Temporary Files
```bash
# Find and remove temporary files
find /tmp -type f -name "*.tmp" -o -name "*.temp" -delete
find /var/tmp -type f -name "*.tmp" -o -name "*.temp" -delete
```

## Step 3: Clean Docker Images (Optional)
If you want to remove specific images, use:
```bash
docker rmi <image_name>
# Or for all images in a volume
docker system prune --all
```

## Step 4: Verify Cleanup
```bash
# Check if containers are gone
docker ps

# Check if temp files were removed
find /tmp -type f -name "*.tmp" -o -name "*.temp" | wc -l

# Check for any remaining Docker-related artifacts
docker system prune --all
```

## Alternative: Use a Script (Recommended)
For automation, create a script to handle this:

```bash
#!/bin/bash
# cleanup_docker.sh

echo "Starting Docker cleanup..."

# Stop containers
for container in $(docker ps --filter "name=.*" --format "{{.Names}}"); do
    docker stop "$container" 2>/dev/null || true
done

# Remove containers  
for container in $(docker ps --filter "name=.*" --format "{{.Names}}"); do
    docker rm "$container" 2>/dev/null || true
done

# Clean temp files
find /tmp -type f -name "*.tmp" -o -name "*.temp" | xargs rm -f 2>/dev/null || true

# Remove Docker images (optional)
docker system prune --all 2>/dev/null || true

echo "Cleanup complete!"
```

## Verification Checklist
- [ ] No `docker ps` showing any containers
- [ ] No `/tmp` containing `.tmp` or `.temp` files
- [ ] No Docker-related logs in `/var/log/docker*`
- [ ] If you reset permissions, verify ownership is correct

---

**Note:** If you're not a root user, the permission reset commands above will fail. You may need to:
1. Use `sudo` for these operations
2. Create a backup first (e.g., `docker cp <container> /tmp/backup.tar.gz`)
3. Or use an alternative cleanup method if you don't want to risk losing data
