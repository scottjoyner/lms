### Secure Deployment Checklist

#### 1. **Network Binding Security**
- [ ] Bind server to `127.0.0.1` or specific IP range (e.g., `192.168.x.x`)
- [ ] Use `bind()` instead of `socket.bind(0, port)` for local-only access
- [ ] Implement rate limiting on the admin endpoint (prevent brute force attacks)

#### 2. **CORS Configuration**
- [ ] Configure CORS to allow only specific origins: `["http://localhost:8000"]`
- [ ] Add a `Access-Control-Allow-Origin` header with proper restrictions
- [ ] Implement CORS headers validation in the frontend (e.g., `csp-report`)

#### 3. **Authentication & Authorization**
- [ ] Never expose API tokens publicly
- [ ] Use JWT-based authentication for all endpoints
- [ ] Add rate limiting to prevent abuse
- [ ] Implement token refresh mechanism if needed
- [ ] Consider using a secure key management service (e.g., AWS Secrets Manager, HashiCorp Vault)

#### 4. **API Token Storage**
- [ ] Store tokens in encrypted storage (AWS S3 with KMS, Azure Key Vault, etc.)
- [ ] Never store tokens in plain text files or README
- [ ] Implement token rotation policy (e.g., every 7 days)
- [ ] Use a secure secret management service for sensitive data

#### 5. **Root User Access**
- [ ] Configure `useradd` with restricted permissions (`sudo -u root`)
- [ ] Set restrictive file permissions on `/etc/passwd`, `/etc/shadow`, and system directories
- [ ] Implement SSH key-based authentication instead of password
- [ ] Use a secure login service (e.g., Docker Compose, Kubernetes)

#### 6. **Container Security**
- [ ] Run as non-root user with proper permissions
- [ ] Set restrictive container volumes (`--volume` options)
- [ ] Implement network isolation if possible
- [ ] Enable security groups for the container network (if using Docker)
