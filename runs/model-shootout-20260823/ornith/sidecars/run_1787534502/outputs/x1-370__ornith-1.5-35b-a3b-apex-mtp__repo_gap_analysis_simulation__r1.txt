## Implementation Cycle Plan

### P0 â Critical (block any release)

**Security:**
1. **Eliminate RCE via shell command endpoint.** This is arbitrary code execution on the host with no auth gate. Options, in order of preference: remove it entirely; if business-required, replace with a strict allowlist of commands executed without `shell=True`, fully parameterized, validated against a fixed argument schema, and run as a non-privileged user.
2. **Add authentication & authorization.** No auth means unauthenticated access to all data endpoints *and* (currently) the shell. Implement token/session auth (OAuth2 + JWT or server sessions), password hashing (argon2/bcrypt), and role-based route protection. This is foundational â everything else assumes it exists.
3. **Harden error handling.** Weak handlers risk leaking stack traces, DB schemas, secrets, and internal paths to clients. Add global exception handlers returning safe generic responses while logging details server-side; never surface SQL or file paths in API output.

**Logic gap:** No auth + shell endpoint = no authorization boundary at all. Verify there's no implicit trust on request headers/params used for security decisions.
